# История задач

## 2026-10-22 19:12 — Настольное приложение ImageResizer (Windows + macOS)

**Начало:** 2026-10-22 19:12 (Europe/Moscow)

### Задача

Сделать настольное приложение, которое автоматически собирается под Windows и macOS в один
исполняемый файл без зависимостей. Приложение должно для всех картинок, лежащих в той же папке,
где находится сам исполняемый файл, создавать JPEG-копии каждой картинки размерами 762x1100 и
1524x2200 с максимальным весом файла 5 МБ; к именам созданных картинок добавлять префикс-разрешение.

### Уточнения от пользователя

- Картинки с другими пропорциями — кадрировать по центру (заполнять кадр, без полей).
- Автоматическая сборка — GitHub Actions + локальные скрипты.

### Ход работы

- 19:12 — рабочая папка `C:\My\ImageResizer` сначала была заблокирована правами Windows
  (песочница не могла выдать себе доступ: `Win32 5 grantWrite`). Проблема снята штатным скриптом
  диагностики прав; резервные копии прав лежат в `_sandbox-acl/`.
- 19:40 — начата реализация: Python 3 + Pillow + PyInstaller (onefile), ядро обработки в
  `src/resizer.py`, консольный вход `src/image_resizer.py`, спека `ImageResizer.spec`.
- Сборка: `tools/build.ps1` (Windows) и `tools/build.sh` (macOS), CI в
  `.github/workflows/build.yml` (windows-latest, macos-15, macos-15-intel).

**Завершение:** 2026-10-22 19:46 (Europe/Moscow)

### Что сделано

- `src/resizer.py` — ядро: поиск картинок в папке (без подпапок), исключение своих же
  копий по префиксу-разрешению, разворот по EXIF, заливка прозрачности белым,
  кадрирование по центру (`ImageOps.fit`), подбор качества JPEG бинарным поиском
  (максимальное качество, при котором файл ≤ 5 МБ), атомарная запись через временный файл,
  защита от перезаписи чужих не-JPEG файлов, суффикс `_1` при совпадении имён.
- `src/image_resizer.py` — консольный вход: папка определяется по `sys.executable`
  (а не по текущей папке), UTF-8 вывод, сводка, `--dir`, `--no-pause`, коды возврата 0/1/2,
  пауза «Нажмите Enter» при запуске двойным щелчком.
- `ImageResizer.spec` — onefile-сборка PyInstaller, без numpy/tkinter.
- `tests/test_resizer.py` — 17 тестов (размеры, префиксы, кадрирование, лимит веса,
  битые файлы, повторный запуск, коллизии имён, прозрачность, CMYK/серый, GIF, регистр).
- `tests/smoke_test.py` — проверка уже собранного бинарника.
- `tools/build.ps1` (UTF-8 BOM, чтобы Windows PowerShell 5.1 читал кириллицу) и
  `tools/build.sh`; `README.md`; `.gitignore`.
- CI: три сборки — `ImageResizer-windows-x64.zip`, `ImageResizer-macos-arm64.tar.gz`,
  `ImageResizer-macos-x64.tar.gz`; в каждом прогоне бинарник проверяется smoke-тестом,
  по тегу автоматически публикуется релиз.

### Результат проверки

- Все 17 тестов ядра проходят на Python 3.14 / Pillow 12.2.0.
- `dist\ImageResizer.exe` собран (14,2 МБ), smoke-тест пройден.
- Ручная проверка: кириллические имена файлов и папок, JPEG/PNG/WEBP/AVIF/прозрачный PNG,
  запуск из чужой текущей папки (`C:\Windows`) — 5 исходников, 10 корректных копий,
  повторный запуск не создал ни одного лишнего файла; вывод в UTF-8; коды возврата 0 и 2 верны.
- Сборки под macOS в этой песочнице нет (PyInstaller не кросс-компилирует) — их выполняет
  GitHub Actions на `macos-15` и `macos-15-intel`.

### Публикация на GitHub (19:47–19:58)

- Отдельный доступ не потребовался: в Windows Credential Manager уже был действующий
  токен GitHub для учётной записи `kostin` (права `repo`, `workflow`).
- Репозиторий `kostin/ImageResizer` уже существовал (публичный) с README-заглушкой и
  MIT LICENSE. Истории объединены через `--allow-unrelated-histories`: LICENSE сохранён,
  README заменён на проектный, конфликт разрешён в пользу проектного README.
- Первый прогон CI: macOS arm64 и macOS x64 — успех, Windows упал на smoke-тесте
  (`UnicodeEncodeError: charmap / cp1252`). Причина не в приложении, а в самом тесте:
  Python на Windows-CI печатает русский текст в cp1252. Исправлено — `tests/smoke_test.py`
  переводит stdout/stderr в UTF-8. Повторный прогон: все три сборки успешны.
- Тег `v1.0.0` → релиз с тремя файлами. Проверено: macOS-бинарники — настоящие Mach-O
  (arm64 и x86_64) с правами 755, Windows-архив 14,4 МБ.
- Ссылки: <https://github.com/kostin/ImageResizer>,
  <https://github.com/kostin/ImageResizer/releases/tag/v1.0.0>.


## 2026-10-22 20:00 — Прогресс-бар и краткий отчёт

**Начало:** 2026-10-22 20:00 (Europe/Moscow)
**Завершение:** 2026-10-22 20:06 (Europe/Moscow)

### Задача

Показывать во время работы прогресс-бар с обрабатываемыми файлами, а по завершении —
краткий отчёт.

### Что сделано

- Ядро (`src/resizer.py`) теперь сообщает о ходе работы событиями `ProgressEvent`
  (`begin`/`start`/`size`/`done`/`error`/`end`) с номером файла, общим количеством,
  долей прогресса и короткой подписью; `Summary.warnings` собирает предупреждения.
- Новый модуль `src/progress.py`: полоса вида
  `[████████░░░░░░░░░░░░] 5/12 — фото 7.png — 1524x2200 → 2.61 МБ`. Ширина полосы
  подстраивается под терминал, длинные имена обрезаются по центру, сообщения журнала
  печатаются над полосой, после чего полоса перерисовывается. Для консолей без юникода
  есть ASCII-фолбэк `#`/`-`.
- Вне терминала (CI, перенаправление в файл) полоса отключается автоматически, чтобы
  лог не засорялся возвратом каретки; принудительно — ключ `--no-progress`.
- Итоговый отчёт: `Итог: 4 картинки → 8 копий, 3.35 МБ, время 0.5 с, ошибок 0`,
  разбивка по разрешениям, списки ошибок и предупреждений, русские склонения,
  минуты при долгой обработке.
- Ctrl+C: полоса убирается, печатается «Прервано пользователем», код возврата 130.
- В шапке вывода появилась версия (1.1.0).

### Проверка

- 29 тестов: 21 по ядру (включая последовательность событий прогресса и сбор
  предупреждений) и 8 по отрисовке, среди них интеграционный прогон с реальными
  картинками и проверка, что кадр не шире терминала.
- Кадры отрисованы при ширине 80 и 46 символов — обрезка и приоритеты корректны.
- Собран `dist\ImageResizer.exe` (14,2 МБ), smoke-тест прошёл; отчёт в консоли выглядит
  как задумано.
- CI на трёх платформах — успех; релиз `v1.1.0` с тремя файлами:
  <https://github.com/kostin/ImageResizer/releases/tag/v1.1.0>.
